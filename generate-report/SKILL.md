# 研究报告写作：顶级机构规范

核心立场：**一篇报告的专业度不取决于写得多长，而取决于四件事——有没有一句话说得清的核心论点、有没有反共识的张力、每个论断有没有挂得住的数字，以及只读标题能不能复述全文。** 这四件事做到了，8 页也是好报告；做不到，60 页也只是资料汇编。

方法论样本：麦肯锡《Global Private Markets Report 2025》《The State of AI 2025》、Gartner《Top Strategic Technology Trends 2025/2026》与魔力象限、BCG《AI Radar 2025》、贝恩《Global Private Equity Report 2025》、德勤《Tech Trends 2025》、PwC《28th Annual Global CEO Survey》、IDC Worldwide Spending Guide、Forrester《Predictions 2026》、WEF《Global Risks / Future of Jobs Report 2025》、IMF《WEO》与世行《GEP》。

## 何时用本 skill

- 从零撰写一份研究报告 / 行业研究 / 趋势预测 / 白皮书 / 年度盘点 / 调研报告
- 把一堆零散材料（访谈、数据、搜索结果、内部文档）组织成一篇结构完整的报告
- 改写润色一篇已有报告，提升结构与论证质量
- 评审一篇报告并给出可执行的修改清单（百分制量表见 REFERENCE.md §6）

不适用：会议纪要、周报、代码/接口文档、学术期刊投稿格式、PPT 视觉设计。投资标的的**内容**研究交给 `deep-company-analysis`（公司深度）/ `analyze-value`（估值）/ `analyze-dip`（暴跌决策），本 skill 负责把结论组织成机构级报告的**形式**。

## 快速上手

1. 先跑**阶段 0 立项三问**（见下）——三问答不出来就不要动笔，先补研究。
2. 读 [REFERENCE.md](REFERENCE.md)：12 个内容构件、8 条共性铁律、单章五拍模板、图表规范、评审量表。
3. 若用户的需求命中某个**体裁模板**（见下），直接读该模板文件按它的流水线走——模板里已经把骨架、打分模型、表格规范与坑都写好了。
4. 若用户指定「像某家机构那样写」，读 [PLAYBOOKS.md](PLAYBOOKS.md) 对应条目，套用该机构的结构与图注习惯。
5. 先交**骨架**（标题 + 副标题 + 执行摘要要点 + 各章 Action Title 一览）给用户确认，再展开正文——避免写完 30 页才发现论点跑偏。
6. 交付前逐项过**阶段 3 质检清单**，把结果写出来，不合格项当场修。

## 阶段 0：立项三问（动笔前必须回答）

1. **核心论点（thesis）是什么？** 一句话，且这句话能直接当副标题。
   例：BCG《From Potential to Profit: Closing the AI Impact Gap》。
2. **反共识点在哪？** 找到「大众以为 X，数据证明 Y」的张力——悖论、差距（gap）、拐点。
   例：麦肯锡「88% 的组织在用 AI，但只有 33% 在规模化」；PwC「60% CEO 看好增长，42% 认为公司撑不过十年」。找不到张力，说明问题不够锋利，换一个问题。
3. **数据从哪来？** 逐条列出关键论断 → 数据来源 → 统计口径。自有调研先定样本设计（对象、样本量、时间窗、地区/行业分布、加权方式）；二手数据写明数据库名与检索日期。

三问的答案写进报告顶部的工作区文件（见「交付格式」），后面每一章都回头对照。

## 阶段 1：搭骨架（先结构，后内容）

标准 9 段式骨架，按报告规模裁剪：

```
1. 标题 = 主标题（画面感） + 副标题（核心论点）
2. 执行摘要：3–7 条「数字 + 判断」，可独立成篇
3. Why now：为什么此刻值得读（环境变化 + 问题定义）
4. 方法论说明：数据来源、样本、时间窗、口径、局限
5–7. 核心发现（3–8 章），每章按五拍展开：
      现状(What) → 拐点(Change) → 驱动(Why) → 分化(So what) → 前瞻(Now what)
      每章至少：1 个量化发现 + 1 张图表 + 1 个具名案例
8. 预测与展望：年份 + 数字 + 基线，可证伪
9. 分角色行动建议 + 风险与不确定性 + 署名/来源/免责
```

**章节切法三选一**（不要混用）：

| 切法 | 适用 | 对标 |
|---|---|---|
| 议题并列式 | 趋势 / 预测类 | Gartner 十大趋势、德勤六大趋势、Forrester Predictions |
| 价值链 / 维度式 | 行业年度盘点 | 贝恩「投资—退出—流动性—募资—回报」、麦肯锡按资产类别 |
| 总-分专题式 | 宏观 / 政策类 | IMF「全球展望 + 专题章」+ Box + 统计附录 |

**规模档位**（决定裁剪哪些构件）：

- **简报（1–2 页）**：标题 + 执行摘要 + 2–3 个发现（各一拍到三拍）+ 一句话建议。方法论压成一行脚注。
- **标准（8–15 页）**：9 段式全上，3–5 章发现，每章一图。
- **旗舰（30 页+）**：9 段式 + 专题章 / Box + 统计附录 + 完整数据来源清单 + 致谢署名。

## 阶段 2：语言与证据规范（逐条执行）

1. **结论先行**：报告、章、段三级倒金字塔。执行摘要=全文压缩，每章首段=该章压缩，每段首句=该段论点。读者在任何一层停下都已拿走该层最重要的信息。
2. **Action titles**：所有标题（含图表标题）写成完整判断句，不用名词短语。
   ❌「募资情况」→ ✅「除亚洲外，各地区并购基金募资全线下滑」。
3. **一段一论点**：首句是论点，其后是证据；段落不超过 5 行。
4. **每个论断挂数字**：禁用「显著增长」「广泛采用」「大幅提升」这类空词，改为具体百分比、金额、样本量、同比变化。
5. **预测三要素**：时间锚（by 2028）+ 量化（15%）+ 基线（up from 0% in 2024）。缺任一要素的预测不许出现。
6. **图表三件套**：编号（图 1 / Exhibit 1）+ 结论式标题 + 来源与口径注释（Sources / Notes）。口径注释要写清剔除了什么、含不含未完成项、金额阈值。
7. **案例具象化**：用具名公司、交易、事件佐证抽象论点（贝恩式：「KKR 以约 100 亿美元收购 Cotiviti」）。
8. **提炼一个框架**：把核心发现压缩成一个可命名的模型、数字口诀或矩阵（BCG「10-20-70」、Gartner 魔力象限）。框架是报告被引用和传播的最大杠杆——一篇报告至少给一个。
9. **承认不确定性**：固定设「风险与局限」段；预测给区间或情景（基准/乐观/悲观），不装确定。
10. **分角色收尾**：建议按读者角色拆开写（CEO / 董事会 / 投资者 / 业务负责人 / 政策制定者 / 执行层），终点永远是「你，下一步做什么」。

## 阶段 3：质检清单（交付前逐项过，把结果写出来）

- [ ] 副标题是否就是全文论点？
- [ ] 只看执行摘要 + 所有标题，能否复述全报告？
- [ ] 每个关键论断是否都有数字和来源？
- [ ] 方法论是否写明样本 / 时间窗 / 口径 / 局限？
- [ ] 是否至少有一个原创框架或可命名模型？
- [ ] 预测是否全部带时间锚 + 数字 + 基线？
- [ ] 是否有反共识钩子（gap / 悖论 / 拐点）？
- [ ] 建议是否分角色、可执行？
- [ ] 是否包含风险 / 不确定性声明？
- [ ] 图表是否都有编号、结论式标题、来源、口径注释？

需要打分而非自查时，用 REFERENCE.md §6 的百分制量表（10 项 × 10 分）。

## 数据诚信红线（不可协商）

- **禁止编造**统计数据、样本量、市场规模、增长率、引用与受访者数量。数字只能来自用户提供的材料，或本次实际检索到的来源。
- 每个二手数字标注**来源 + 检索日期**；来源之间冲突时并列两个数字并说明口径差异，不要取平均掩盖分歧。
- 无真实来源的前瞻数字，标为**【情景假设】**并写出推导假设，不得写成事实。
- 用户材料里的数字与公开来源不一致时，指出差异，让用户裁决，不要自行改写。
- 推测性判断统一标 **【推测】**。

## 报告体裁模板

某些报告需求形态固定、可整套复用。命中时**先读模板文件，再动笔**——模板给的是这一体裁专属的骨架、评分模型、表格规范与踩过的坑。

| 模板 | 命中信号 | 文件 |
|---|---|---|
| 多主体 × 方向打分 × 产业链 × 公司投资图谱 | 中长期（3-10 年）+ 枚举方向 + 0-100 打分排序 + 中美/多主体分别成章 + 产业链上中下游 + 逐公司「是否值得投资」+ 周 K 线图与指标表 | [templates/two-country-scoring-investment-map.md](templates/two-country-scoring-investment-map.md) |

该模板配套脚本 `scripts/fetch_market_data.py`：一条命令批量拿到全部标的的近 1.5 年周 K 线 PNG、股票指标表与近期财报表（Markdown 直接粘进正文）。

```bash
uv run --script scripts/fetch_market_data.py \
    --tickers MSFT CRM NOW 0700.HK 002230.SZ \
    --output-dir reports/2026-09-01-<topic> --weeks 78
```

## 交付格式

默认工作区（除用户另有指定）：`reports/YYYY-MM-DD-<topic>/`

```
reports/2026-09-01-china-ai-infra/
├── brief.md      # 阶段 0 三问 + 骨架 + 章节 Action Title 一览（先给用户确认）
├── report.md     # 正文（Markdown，图表用表格或 mermaid，图注含 Sources/Notes）
├── sources.md    # 数据来源清单：来源名 + 链接 + 检索日期 + 对应论断
└── exhibits/     # 图表数据与图片（可选）
```

- 语言默认跟随用户提问语言；中文报告的标题、图注、术语保持中文，机构名与专有指标可中英并列。
- 需要 Word 交付时，用本仓库的 **`markdown-to-docx`** skill 把 `report.md` 转成带目录、表格样式与 Mermaid 图的 `.docx`，不要手写 docx。
- 长报告采用**分章递交**：一章写完即请用户确认，再写下一章，避免论点漂移。
